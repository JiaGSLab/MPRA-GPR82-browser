Codex C1-2000 与 Claude v7：实际文件比较
2026-10-02；本报告比较的是此时的文件快照，不覆盖以后 Claude 对 v7 的修改。

版本名称
Codex C1-2000：基于冻结 v6 文库的第一版压缩方案。1998 条已有序列 + 2 个待设计单倍型单突变名额；200 bp insert，总长 230 nt。C1 尚不是完成质控的合成库。
Claude v7：当前 v7_2000 目录中的实际设计。2000 条已有序列；170 bp insert，总长 200 nt。
不要把 C1 叫成 v7 或 v8。两个版本是不同取舍，不是单纯前后升级。

两个版本共有 633 个变异；C1 独有 58 个，v7 独有 173 个。v7 净多 115 个变异。
在原 v6 中 gnomAD_AF_grpmax >= 1% 的 134 个位点里，C1 保留 123 个，v7 保留全部 134 个。这是 v7 对跨人群常见位点覆盖的实际优势。本口径包含手工/古人类分层中的位点，所以不能与只统计某一层的“98 个”等数字混用。

区域取舍
R01：C1 13 个变异，v7 7 个；R02：5 对 1。
R06：99 对 104；R09：125 对 282；R10：42 对 7。
v7 把更多预算放到 GPR82 启动子所在 R09，C1 对外围候选更均衡。R09 扫描覆盖实际上 v7 更高（7826 对 7656 bp），所以“v7 总覆盖率更低”不代表每个区域都更差。
R01 扫描覆盖 C1 为 400/500 bp，v7 为 370/500 bp。两者均有缺口；都不应写成 gap-free 或 100% 覆盖。
逐区数据见 C1_vs_v7_regions.json，逐位点交集见 C1_vs_v7_variant_membership.tsv。

v7 的优点
1. 已有完整 2000 条序列，可执行程度比 C1 的预算方案更高。
2. 少量窗口承载更多不同变异，变异广度更高，并主动保留部分人群中常见的位点。
3. 所有手工/已入库古人类/Sheet3 核心位点均保住，并普遍安排正反方向比较。
4. 对照预算更充足；已有供应商复核表列 13 条风险项，而 C1 的现有序列中保留 20 条原 v6 风险项。风险清单不是供应商拒单结论。

C1 的优点与局限
1. 重点位点保留 3 个不同基因组窗口，能更直接检查序列背景依赖性；v7 的正反向属于同一基因组窗口，不能替代不同窗口。
2. 保留 200 bp insert 与原扫描范围，整体空间覆盖更高。
3. 使用本轮重新求交的远端 DNase/H3K27ac/STAT3 证据，避免将原漏注释位点全按低优先级处理。
4. 不足是变异广度较小、对照较少，且 A/B 只是预留，还没有成为可合成序列。C1 的均衡分配是透明启发式，不是统计上的全局最优。

v7 需要改正的具体问题
P1：同一背景的单倍型 A、B 单突变缺失。
  现有 REF 为 GPR82v7_00814，AB 为 GPR82v7_00815。对全部 2000 条实际 insert 做正反向匹配，均未找到相同窗口的 A-only 或 B-only。普通 SNP 的其他窗口不能替代它们。因此当前版本不能据此估计 A 与 B 的交互/非加和效应。
  此窗口 170 bp，两端侧翼各 9 bp。即使补齐四状态，也只能解释这一截短背景下的交互；“边缘效应是常数所以必定抵消”不成立，因为截短背景可能改变等位基因效应本身。可考虑给这一模块单独保留较长窗口，但需确认混合长度的克隆与合成兼容性。

P2：摘要存在复制残留。
  design_summary.json 的 unique_complete_length_nt=230、CRS_length_bp=200 与实际 200/170 不符。其 haplotype_note 仍写未设计，与实际已有 REF/AB 不符；motif 状态、v6 相关比较文字也存在旧版残留。当前 independent_validation.json 通过并不能自动证明所有说明文字正确。

P2：旧浏览器导出中 56 条 ladder 对照坐标多了 30 bp。
  GPR82_v7_negative_and_activity_controls.bed 中，这 56 条区间长 200 bp，而实际 insert 为 170 bp。新浏览仓库独立按 v7_control_ladder.json 原始窗口及 offset 重建为 170 bp，未改动原 v7 文件。

P2：远端证据注释仍有漏项。
  当前 v7 入库变异里发现 7 个 DNase/H3K27ac 注释与原始峰重新求交结果不符，集中于 R01。原分层和排序可能因此低估远端候选；新浏览轨道显示重新复核的证据，保留原 variant tier 标签以避免悄悄改写版本。

解释需收紧：archaic_class 的命名。
  代码将没有现代数据库记录的位点命名为 archaic_specific_no_modern_record，将现代中稀有的命名为 archaic_specific_rare_in_moderns。“数据库未见/低频”不等于“古人类特有”，应改成直接描述观测事实的标签。保留现代主要等位基因与 hg38 少数等位基因的区分，是正确方向。

解释需收紧：方向一致性。
  正反向是有用的稳健性检查，但“只在一个方向出现就不是等位基因效应”过于绝对。方向、片段边界和报告构型可以改变测到的调控效果；需要检查方向交互，而非机械否定单方向信号。

独立核查已通过的部分
实际 v7 为 2000 个唯一 ID / 唯一全长序列，全部 200 nt、insert 170 bp。897 个 REF/ALT 比较均完整，在记录位置仅有正确的单碱基差异；其正向 REF insert 均与缓存 hg38 参考一致。以上不是仅引用 Claude 自己的 pass，而是本轮重新计算。
v7 FASTA 快照 SHA256：71b435f3ce5e5f05698267bc27390ba73eb91305afb34fdc69b49e2eb3ad69e0

如何选择
若第一目标是广泛发现更多候选，v7 更合适，但先修正单倍型模块、元数据和浏览器导出。
若第一目标是验证手工/古人类重点并检查背景依赖，C1 的配置更贴近目标。
我建议以 v7 的可执行文件与跨人群覆盖为基础，吸收 C1 的重点多窗口和证据复核，再重新平衡 2000 条，而不是把当前任一版直接称作无问题终稿。这是建议，本轮没有产生第三套合成设计。
两版同为 2000 条。在每片段条形码数、覆盖与重复数相同时，细胞规模主要相同；把 insert 从 200 缩到 170 bp 本身不会再把细胞需求降低。170 bp 并非原则上不能用，但较短背景带来的测量差异不能忽略。
